# 平台接入与验收

## 当前完成范围（2026-09-15）

本地已完成 Go 服务、核心场景测试、性能基准、Linux 启动验证、Linux 竞态检测、候选包冻结、可恢复的平台流程及日志自动复盘。**尚未上传到比赛平台，尚无官方实战或胜率证据。**

平台适配器必须根据真实接口实现；下面的 `action` 是本地适配器契约，不是远端 HTTP 路由。当前没有真实适配器，也没有模拟胜率。

## 1. 地图预检

```powershell
$env:GO111MODULE='on'
go run ./cmd/preflight -config configs/default.json -request docs/request.txt
```

当前默认配置预期以非零码退出，并报告缺少 `challenger` 的 verified profile。程序检查配置、坐标、占格和武器操作位。需要分别输入双方第一回合快照；它不会从 Demo 猜测合法建造区，也不能证明手工填写的 `verified:true` 符合官方地图。

待提供：双方第一回合请求 JSON、官方蓝色武器区/黄色墙区坐标或可读地图。拿到地图后应先核验配置，再用官方判题器验证建造、移动、弹道和冷却。

## 2. 测试与冻结发布包

```powershell
./scripts/test.ps1 -Bench
./scripts/package.ps1 -LocalOnly
```

`-LocalOnly` 明确生成尚未通过官方地图检查的本地包。正式配置使用：

```powershell
./scripts/package.ps1 -ConfigPath configs/official.json -ChallengerRequest path/to/challenger-round1.json -DefenderRequest path/to/defender-round1.json
```

脚本先冻结白名单源码，再在冻结目录运行单测、vet 和 Linux 构建。目录为 `iteration/releases/<时间-随机编号>/`：

- `source.zip`：Go 源码、所选配置、启动脚本和测试请求。
- `linux-amd64.zip`：Linux agent、启动脚本及所选配置。
- `manifest.json`：工具链、文件 SHA-256、检查范围及 `officialBattleVerified:false`。
- `test.txt`、`vet.txt`：冻结源码的验证记录。

源码包与二进制包采用哪一个、运行架构、目录层级、大小限制和编译命令，必须依据平台上传规范决定。脚本不覆盖旧候选。发布包排除 IDE 文件、历史日志与凭据。

`run.sh` 默认加载包内 `configs/default.json`；`AGENT_CONFIG` 可显式覆盖。

## 3. 真实平台适配器契约

适配器是明确指定的可执行程序，通过 stdin 接收单个 JSON，通过 stdout 返回单个 JSON。执行器不经过 shell；凭据通过环境变量传入。stdout 禁止打印杂项或凭据；stderr 不归档。响应上限 64 MiB，每次操作超时 30 秒。

请求字段：`action`、`operationId`、`artifact`（本地冻结 ZIP 绝对路径）、`sha256`、`versionId`、`matchId`。

| action | 响应要求 |
| --- | --- |
| `upload` / `lookup_upload` | `status:"found"`、真实 `versionId`、匹配的 `sha256`。未知时不返回 found。 |
| `get_version` | `status:"pending"/"ready"/"failed"`、`versionId`、`sha256`。 |
| `start_match` / `lookup_match` | `status:"found"`、真实 `matchId`、接受的 `versionId`。 |
| `get_match` | `status:"pending"/"finished"/"failed"`、ID；完成时还需 `fullMatch:true` 和 `result:"win"/"draw"/"loss"`。fullMatch 指完整上下半场。 |
| `download_logs` | `versionId`、`matchId`、`logs:[{name,data,sha256}]`；data 是原始程序记录 JSON 字节的 base64，sha256 是这些字节的摘要。 |

适配器负责调用官方接口、版本绑定核验、对手/种子/测试场配置、完整结果留存、链接刷新和平台节流。不能仅回显请求中的 hash 来冒充版本核验。若平台无法确认版本或操作受理状态，应返回未知或失败，不能猜测。

原始裁判日志与编译日志需由真实适配器另行保存在候选证据目录；当前下载契约针对可被本程序重放的 `record.Entry`，并非任意平台 ZIP 的通用解析器。

## 4. 执行与中断恢复

以下命令中的路径是占位符；真实适配器尚未实现，当前不能执行平台操作。

```powershell
go run ./cmd/iterate -dir iteration/candidate-001 -init path/to/tested-release.zip
go run ./cmd/iterate -dir iteration/candidate-001 -adapter path/to/official-adapter.exe -run
```

初始化只冻结包并写状态，不上传，不代表通过准入检查。操作前必须按第 1、2 节完成检查并核对平台上传规格。`-run` 最多执行一个候选的一场完整比赛，期限为初始化后 60 分钟；轮询间隔 5–30 秒，超时或未知响应即停止。单步控制用 `-step`；查看已有状态只传 `-dir`。不自动购买额度、不修改正式生效版本、不自动晋级最佳版本。

状态链：

```text
Prepared → UploadPending → Uploaded → BuildPassed
→ MatchPending → MatchRunning → MatchFinished → Inconclusive
```

- 上传和开赛前保存 operationId 和 pending 状态；断线后只执行 lookup，不自动重新提交。
- 每个候选具有随机标识，操作号跨重启稳定，不与另一个候选共用。
- 编译失败、版本不匹配停止；日志校验失败保留 `LogsIncomplete`，可单步重取。
- `state.json` 使用临时文件写入、Sync 和 Rename；`ledger.jsonl` 留存操作意图及结果。
- `runner.lock` 防止两个执行器同时推进。进程硬崩溃后锁可能保留；确认没有活动执行器后再移除该锁。不要删除 state 或手动把 Pending 改回 Prepared。
- `-run` 到期保留原状态；已提交比赛可用 `-step` 做只读查询和取日志。过期候选不再提交新的上传或比赛。
- 日志下载后自动校验、重放，产出 `review.json`，但单场比赛统一标为 `Inconclusive`；这不是多候选胜率评估或自动代码修复器。后续按项目循环迭代方案做独立配对评估。

## 5. 自动复盘

```powershell
go run ./cmd/review path/to/record-directory
```

输出服务异常、判题错误、上一回合非法动作、响应/Memory 差异、记录中的 P99/最大耗时。只重放 `decided` 记录，不执行日志中的 shell 或模型请求。发现问题时退出码为 1；文档请求自带示例错误，因此该样例报告非零码是预期的。P99 是所提供记录的统计，不是全比赛性能承诺。

有截止预算或不同二进制版本时，重放差异不一定是算法错误。报告用于找到最早有证据的异常，不能仅凭它猜测裁判未返回的原因。

## 6. 实际验证证据

- `iteration/validation/tests.txt`：Windows 单测覆盖率。
- `iteration/validation/race-linux.txt`：Ubuntu/WSL、Go 1.24.1、gcc、`go test -race ./... -count=1`。
- `iteration/validation/benchmarks.txt`：每项 200 ms，重复 3 次的基准。
- `iteration/validation/linux-smoke/result.json`：真实 Linux 进程 HTTP、幂等、SIGTERM 和日志刷新。
- `iteration/validation/linux-review.json`：Linux 日志在当前 Windows Go 实现中的复盘，响应/Memory 差异均为 0；文档样例内的判题错误被检出。

复现 Linux 启动检查：

```sh
python3 scripts/smoke_linux.py path/to/linux-amd64.zip docs/request.txt path/to/new-output-directory
```

该脚本在临时目录解包，并按 ZIP 模式位设置可执行权限后测试。官方平台如何解包和赋权仍需联调。
