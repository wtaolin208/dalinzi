# 作战策略实现与扩展

实现基线为《作战策略.md》，协议依据 `request.txt`、`response.txt` 与 Demo。仅在 `dalinzi` 工程修改；根目录 `main.go` 直接接收端口并启动 HTTP 服务，保持 `POST /` 与响应三个顶层字段不变。`response.txt` 是多种动作的展示，其中有重复 ID 和缺失逗号，不能作为一整条有效响应照搬。

## 结构与职责

```text
main.go → internal/agentapp → internal/server
                               ↓
                    game.Engine.Decide
                    ├─ tasks.go：历史、任务会话、工具结果关联
                    ├─ world.go：时段、结构风险、返航名单
                    ├─ fsm.go：显式转换、意图评估和统一模块调度
                    ├─ score.go / dayplanner.go：比分区间、剩余生存分、逐日建设目标
                    ├─ defense.go：固定炮位与失效重分配
                    ├─ emergency.go：先分配应急物品，再分配炮控
                    ├─ combat.go：可配置武器顺序、联合伤害与击杀评分
                    ├─ task_selection.go / treasure.go：任务、宝藏行动
                    ├─ work.go：工人候选联合分配及资源预约
                    │   ├─ construction.go：八邻域通路与热区墙位评估
                    │   └─ economy.go / market.go：采销周期、预测、储备、补给
                    ├─ offense.go：显式开启的保守召唤策略
                    ├─ navigation_helpers.go / movement.go：联合移动与风险纠偏
                    └─ validate.go：最终合法性与冲突校验
```

仍使用同一个 Go 包共享协议类型和世界状态，不复制状态模型。`legacy_economy.go` 是原经济实现，保留给既有对照测试；生产决策走 `assignWorkers`。不把研究性的历史实现混入新的决策分支。

## 策略对应关系

| 策略要求 | 实现与约束 |
| --- | --- |
| 全局状态先于动作 | `BattlePlan` 先给出昼夜、结构风险与各角色返航名单；模式及转换进入 Trace / Memory。日间建设与任务允许不同角色并行执行 |
| 积分模型 | 剩余生存分采用 550−5×(day−1)×day；任务密度包含去程、求解和返航；安全火力按击杀分/剩余血量评估。部分伤害仅作规划价值，不计为已得分 |
| 敌方比分 | 区分未传 totalScore 与明确的零分；未知总分保留无上界区间，不凭机器人消失认定敌方击杀。只有双方明确总分才能判断领先/落后，否则采用均衡模式 |
| 逐日目标 | 前三天禁止进攻；第 3 天起优先基地/核心炮二级；第 7 天基地三级、墙二级；第 8 天冻结常规墙扩建；第 9 天停止跨天囤货；末期已知领先禁止进攻。建设目标表示优先级，不保证资源不足时达成 |
| 连续夜间风险 | 记录每晚基地预计剩余血量是否低于安全线；第 7 天起若前两晚都触线，关闭施压并将宝藏置信度提高至至少 0.95 |
| 首日三炮 | 只在已核验建造坐标上给三炮建设最高工作优先级，保留缺少炮台所需金币，禁止宝藏购物挪用；不臆造蓝色区域 |
| 固定炮控 | 三名角色和三种炮齐全时按 ID 排序确定 worker1/2，绑定 Gatling/Railgun/Rocket；失败路径、死亡、炮种不全或任务锁定时重新求分配。固定绑定下的寻路最优不等于无绑定的全局最优 |
| 逐角色返航 | 比较到所属炮位的距离与 `returnBuffer`，最紧迫返航优先于任务和普通工作；工人候选和任务准入也预留返航成本 |
| 任务探索与先提交 | `parallelTask` 支持同响应的 prompt/executeCmd，反馈仍按回合和 session 关联。`submitFirst` 先提交可用答案；技能同时验证时，必须沙盒一致且裁判确认任务结束才入库 |
| 不同任务阶段 | TaskMemory 保存 EXPLORE/REFINE/SUBMIT_BASELINE/SUBMIT_BETTER；接受与冷却由请求中的任务状态驱动，退出任务清理会话，学习回执独立保留 |
| 采矿完整收益 | 可见商人存在时计算去矿、可采数量、去商人、出售与返航。没有商人几何信息时仅作探索性采集，不声称完成收益最优证明 |
| 新闻与储备 | 接收结构化价格方向，要求逐字官方新闻引用与置信度；涨价窗口前可持有，缺钱/满包可提前卖。价格溢价是可配置假设，不是官方未来报价。石头储备按全队分配，避免每人重复预留 |
| 墙位与碰撞历史 | 记录实际可见机器人热区；高热通道降低建墙优先级，对主要入口检查八邻域可达和导向炮台的风险。无错误但移动未前进只作为风险迹象，不断言是敌方碰撞 |
| 应急优先 | 升级回血、维修、药剂或范围物品先预约角色动作，火控跳过被占用 controller；范围炸弹预期伤害进入后续联合评分，避免重复投入 |
| 联合火力 | 保留总伤害向量、击杀价值与黎明折扣，默认 Rocket→Railgun→Gatling；敌方目标机器人不获默认防守收益，但弹道仍考虑其实体遮挡假设 |
| Day 10 | 不再为未来涨价囤矿，允许零散资源出售；保留必要石料，降低补给的未来金币储备，评估现有炸弹/眩晕等即时收益 |
| 宝藏反例 | 保存位置、时间、物品和结果码；错误物品组合不因重新排序就重试，成功/已空停止；重新解释新闻时携带历史，购物路径也计入返航成本 |
| 对敌施压 | 默认关闭 `enableOffense`。开启后仍要求三炮、存活角色、健康且升级的结构、应急库存、剩余金币及白天时间；按已发出的合法本地命令保守累计日用量，不超过十张。对手伤害收益是启发式，不能声称已证明击穿 |
| 校验 | 继续检查动作、数组、角色、资源、范围、冷却、锥角、控塔互斥和移动冲突；新增非空答案约束。结果 `false` 不自动当作协议错误 |

## 新增策略如何接入

1. **经济/补给策略**：实现 `workModule(workContext, workSink)`，在 `economicModules()` 注册。模块只提交候选、目标、价值、金币成本和排他键；不要直接覆盖其他角色命令。
2. **建设策略**：必须使用 verified profile 和通路检查；提交 `build:<位置>` 排他键，并在新建筑占格后的联合地图上求路径。
3. **新物品**：在应急/补给候选与 `CommandValidator` 两处增加规则；同时补“使用物品与控制武器不可兼得”的测试。
4. **新战术或预测**：先定义输入、适用条件、收益和回退，再记录进 Trace。未知裁判语义使用显式开关，不能通过放宽校验来让策略看似有效。
5. **参数实验**：在 `StrategyConfig` 提供默认值及校验，更新配置 JSON；使用循环 Skill 的固定基线、配对对照、确认批次和经验入库流程评估。

## 参数与待实测边界

`configs/default.json` 的 `strategy` 段包含石头储备、任务余量、宝藏/预测置信度、风险窗口、应急血量比、炸弹最低有效伤害、武器顺序、任务并行/先提交和进攻开关，另有 taskMinExpectedDensity、lateTaskMaxRounds、scoreMarginBuffer。文档中的 `returnSafetyBuffer` 对应既有配置键 `returnBuffer`，默认 5。

逐日里程碑集中在 `planDay`，候选价值由 `upgradePriority` 决定；调整日程无需改动协议、联合分配和命令校验。任务成功率、求解耗时使用历史统计；最低密度默认 0，由候选相对收益择优，可显式提高准入门槛。无法从现有可见字段可靠收紧敌方任务/宝藏得分上界，所以保留未知，未制造一个有限误差区间。

策略中的建造区、弹道遮挡、矿尾双采、击杀归属、覆盖建造和火箭 PvP 等未知规则，严格保持未核验状态。重复炮弹落点仍由 `allowDuplicateShots` 控制；已有算法支持重叠伤害，正式启用前需要裁判校验。不会因为策略建议而伪造建造区域或物理规则。

结构风险是基于血量、目标阵营、眩晕和邻近距离的保守估计，没有完整机器人运动模拟器，因此不输出“已证明存活概率”。墙体比较也不是破墙行为或炮弹建筑遮挡的证明。

## 验证与交付

回归还覆盖明确零分与未知比分、逐日进攻/建设门槛、生存分公式、击杀密度。

运行 `GO111MODULE=on go test ./...` 与 `go vet ./...`。新增回归覆盖敌方目标过滤、应急动作与炮控互斥、固定炮位/阵亡重分配、任务并行验证与入库、新闻引用、终局出售、逐角色返航、墙位热度、宝藏反例和召唤安全/日限额。

`python pack.py` 冻结 `CoreGeek/src/` 源码，包内 Go 1.24.7、本地 go.mod 不变。`python scripts/verify_submission.py CoreGeek.tar.gz --local-go` 使用本地 Go 检查临时解包副本的测试、vet、Linux 构建与直接 HTTP 启动；不把该结果当作真实平台对战或胜率证据。

## 状态机流转与调度

`assessFSM` 每回合从 Memory 中的上一状态进入 `DAY_ASSESS` 或 `NIGHT_ASSESS`，首次/半场重置先记录 `INIT`。`BattlePlan.transitions` 保存 from、to、reason，`policy` 决定哪些模块可以执行；状态不再根据最终攻击/移动命令事后补标。

- 白天优先级：结构濒危抢修（`DAY_BUILD` 且 emergency）→ 返航/安全中断 → 可行建设、升级和维修 → 可完成任务 → 可行宝藏 → 经济。普通白天模式允许工人和开拓者分工；返航及应急模式关闭普通任务、经济和召唤。
- 建设、任务、宝藏意图在接近目标途中就生效。每次都基于新快照重评估；完成、失效或路线不可行后经 ASSESS 重新选目标。状态代表本回合主导意图，不代表三个角色必须执行同一动作。
- 夜间有己方目标机器人时进入 `NIGHT_DEFEND`，结构濒危时抢占为 `NIGHT_EMERGENCY`；无威胁且无已验证进攻方案时停留 `NIGHT_ASSESS` 并保持就位。
- `NIGHT_OFFENSE` 是受能力验证约束的扩展位。目前无已核验夜间 PvP 方案，因此没有伪造可执行进攻分支。不能以召唤令代替夜间 PvP；召唤由白天调度、offenseTurn 和最终 Validate 三处共同限制。
- 连续三个有动作错误的快照、连续三次移动无进展、连续快照中的移动角色损失，都能中断普通白天状态进入安全返航并重规划。异常消失后重新评估恢复。
- 双方基地均以明确的 station/health 数据确认死亡才提前 END；缺失敌方基地不能当作死亡证据。第 1300 回合仍执行最后一轮动作，随后记录 END；该回合 policy 表示实际派发动作时的策略，transitions 记录最后的终局转换。之后请求不再派发动作，半场/队伍重置可重新 INIT。

测试 `fsm_test.go` 覆盖昼夜/新半场、途中意图、完成回退、升级抢修、应急恢复、返航抢占、安全中断、明确终局、第 1300 回合仍攻击以及夜间召唤校验。HTTP 生命周期用例覆盖两半场各 1300 回合，夜间不再沿用旧用例的采矿行为。
