# 任务技能自动学习、验证与入库

实现入口：`internal/game/learning.go`；由 `taskTurn` 与 `updateMemory` 驱动。沿用 `enableTasks` 和 `enableSandboxCommands` 开关，默认开启。

## 跨回合流程

1. 探索任务时，记录最近四次沙盒命令及结果，单项长度受限。将这些证据与题目、答案一起交给平台 LLM。
2. 解题提示词要求模型同时提炼 `skill`：名称、完整匹配题目的正则、命名参数、Python 脚本、SOP。若模型只返回答案且已有探索结果，额外进行一次技能提炼；模型可返回 null，不能泛化时直接提交答案。
3. 检查模板大小、正则、完整题目匹配以及非空命名参数。将模板作为候选，在当前任务的平台沙盒中重新执行。程序本机不执行模型代码。
4. 必须收到紧邻下一回合的成功退出结果，且输出是未截断的 `{"answer":"..."}` JSON，并与待提交答案完全一致。否则丢弃候选，仍提交原答案。
5. 提交答案后，等待下一回合的判题反馈。必须同时满足：该角色动作明确合法、当前任务已消失、没有错误反馈，才将候选加入 `Memory.Skills`。缺失、迟到、超时、答案错误和任务仍进行中均不入库。
6. 后续题目先匹配人工配置的 Recipe，再匹配可用的学习技能。命中后直接执行脚本，下一回合提交结果，省去 LLM 往返。
7. 已入库技能执行失败、结果格式错误，或提交后有错误反馈，会被停用，并回退到普通 LLM 解题流程。后续可以重新学习、验证；相同技能通过验证后可以重新启用。

## 模型返回示例

```json
{
  "session": "必须与当前任务一致",
  "answer": "12",
  "skill": {
    "name": "integer-addition",
    "pattern": "^add (?P<a>[0-9]+) (?P<b>[0-9]+)$",
    "python": "import json,sys\np=json.loads(sys.argv[1])\nprint(json.dumps({'answer':str(int(p['a'])+int(p['b']))}))",
    "sop": "提取两个整数参数，计算和，输出 answer JSON。"
  }
}
```

脚本参数通过 JSON/Base64 传入，题目不直接拼进 shell/Python 源码。提示词要求模板自包含、可重复执行、只读查询，不依赖前一任务的临时文件。该要求是模型生成约束，不是 Python 静态安全证明；执行隔离由平台沙盒提供。

## 技能库范围和验证边界

- 技能库存于本半场的 `Memory.Skills`，跨任务保留，最多 16 项；满后淘汰最早入库项。记录包括 SOP、脚本、源题哈希、验证回合、成功次数、停用状态。
- 保持确定性序列化，可随现有回放记录保存和重放。没有新增外部数据库，也不在进程重启时自动加载；换边、队伍变化或服务原有状态重置会清空，避免跨沙盒环境使用旧技能。
- 自动提炼额外消耗一次 LLM 往返，候选验证消耗一次沙盒往返。直接随答案附带候选时省去提炼往返。只有已知任务超时回合且留有验证、提交和反馈余量时才学习；超时信息缺失或时间不足时优先交答案。
- 学习还需通过积分回本判断：预计后续复用的速度奖励增益必须超过本题延迟提交的损失。已有匹配技能、危险或回防时间不足时跳过，详见 `积分收益策略.md`。
- 协议没有独立的“答案正确”字段。入库依据是合法提交、任务结束且无错误反馈的组合，不把命令成功或动作合法单独视为答对。
- 原题复现只验证一个样本，不能证明对所有新参数都正确。后续复用继续根据判题结果监测并停用失败技能；尚无官方比赛泛化收益验证。
- `Trace.Notes` 记录提炼校验失败、沙盒验证、入库和停用事件。旧版本日志在新策略下重放可能产生预期差异，应使用对应版本复盘。

## 测试

`internal/game/learning_test.go` 覆盖实际决策入口的学习→验证→判题→任务清空→新参数复用→错误停用，以及命令失败、答案不一致、过期回复、错误正则、临近超时、回合断档和半场隔离。平台 LLM 与沙盒反馈使用合成协议数据；不代表已完成官方实战验收。
